# AstrBot QQ 官方群管

面向 **QQ 官方机器人**的 AstrBot 群管理插件，覆盖腾讯当前文档「群聊管理」目录的 **17 个接口**，支持 QQ 客户端原生指令菜单和消息内 Markdown 快捷按钮。成员、禁言、黑名单、入群审批和自动审批策略均可用短命令操作；参数完整后直接鉴权、执行并记录审计，不需要再次确认。

本插件使用 QQ 官方 OpenAPI，适用于 QQ 群。它不使用个人 QQ 协议，也不把频道（Guild）的群管接口套用到 QQ 群。

管理命令直接使用，不需要添加前缀：

```text
/禁言 @成员
/禁言 @成员 30分钟
/禁言 @成员A @成员B 10m
/解禁 @成员
/移出 @成员
/菜单
```

`/禁言 @成员` 默认禁言 **10 分钟**。请使用 QQ 的成员选择功能插入真实 @；手工输入一段 `@昵称` 文字不能确定成员身份。如果机器人账号只接收 @机器人 的消息，需要同时 @机器人 来触发，例如 `@机器人 /禁言 @成员 10m`；@机器人 用于唤起，@成员 才是管理目标。

**v1.2 支持安装真正的 QQ 群指令菜单。** AstrBot 管理员在目标群发送一次 `/设置菜单`，插件为当前群创建或更新一份含 20 个常用短命令的官方面板。用户点击 `/禁言` 后，在 QQ 输入框选择 @成员、填写可选时长并发送，即可执行。`/菜单` 则打开消息内的快捷按钮；`/面板` 保留为旧别名。详细行为见 [原生指令菜单](docs/COMMAND_MENU.md)。

**v1.2.2 补充菜单空页兼容和纯文本诊断。** 当列表省略 `records` 或返回 `null`，且只有已知字段和明确的末页标记时，兼容为空页；未知结构仍停止修改。错误回复使用纯文本，原样保留 `INVALID_RESPONSE` 等代码，并附安全的 `response_shape` 字段结构摘要。v1.2.1 中区分执行阶段、创建/更新异常后只读核实的行为继续保留。

## 功能与实际开放条件

| 功能 | 已实现的操作 | 腾讯平台条件 |
|---|---|---|
| 群与机器人信息 | 群资料、群人数、机器人角色、主动消息开关、接收消息模式 | 群资料/机器人状态接口需要平台白名单 |
| 群成员 | 分页列表、成员详情、批量移出、移出并拉黑 | 成员相关接口目前为内邀/白名单 |
| 禁言 | 成员禁言、更新禁言时间、解禁、批量操作、查询群禁言状态 | 机器人须为群管理员；最多 20 人/次，最长 30 天 |
| 黑名单 | 分页查看、添加、移除 | 内邀/白名单；单独添加时目标须已不在群中 |
| 入群申请 | 按需拉取、查看验证消息/问答/风险提示、同意、拒绝、拒绝并拉黑 | 机器人须为群管理员 |
| 自动审批策略 | 列表、创建、修改、删除、执行、增删 QQ 号码白名单 | 作用于机器人关联的多个群；插件仅允许 AstrBot 管理员操作 |
| 消息管理 | 最近两分钟可见消息 ID、撤回、普通通知、@全体通知 | 撤回限 2 分钟内；撤回普通成员消息需机器人为管理员；@全体每群每天 1 次 |
| QQ 原生指令菜单 | 为当前群安装、查询、移除含 20 个常用指令的官方面板，重复安装识别并重用 | 机器人最多 20 份面板；安装和移除仅 AstrBot 管理员；以账号实际 API 权限为准 |
| 消息快捷按钮 | 原生 Markdown、输入按钮、直接执行回调、分页、文本降级 | 需账号实际按钮权限和 AstrBot 原生互动事件支持 |
| 审计 | 本群最近操作记录、部分失败和结果未知提示 | 本地 SQLite 保存，可配置保留时间 |

**插件已实现接口不等于机器人账号已获得接口权限。** `11253` 表示腾讯未授权此接口，需要向 QQ 开放平台申请白名单/内邀。配置插件管理员只能授予本插件的操作权限，不能绕过腾讯权限、机器人群身份或消息配额。

协议核验日期为 **2026-11-12**。完整端点、请求/响应及官方来源见 [API 核验](docs/API.md) 和 [原生指令菜单](docs/COMMAND_MENU.md)；消息内按钮交互见 [按钮说明](docs/BUTTONS.md)；事件支持边界见 [事件说明](docs/EVENTS.md)。

## 安装

要求 **AstrBot ≥ 4.29.4、Python ≥ 3.12**。支持 AstrBot 的 `qq_official` 和 `qq_official_webhook` 平台适配器。请先在 AstrBot 中配置并连接 QQ 官方机器人，确认它能在目标群收到 @ 消息和回复。

1. 将本项目完整解压到 AstrBot 的 `data/plugins/astrbot_plugin_qqofficial_admin`。目录内应直接包含 `main.py`、`metadata.yaml`、`_conf_schema.json`、`requirements.txt` 和 `qq_admin/`，不要多套一层同名目录。
2. 在 AstrBot WebUI 重载插件或重启 AstrBot。框架通过 `requirements.txt` 安装依赖；当前运行依赖为 `aiohttp>=3.11.18,<4`。
3. 在插件配置中按需要设置允许的群和受信任管理员。需要禁言、审批、撤回其他成员消息、@全体时，在 QQ 群内给机器人相应管理员身份，并完成平台接口授权。按钮需要 `INTERACTION_CREATE` 互动事件订阅；使用 webhook 时检查 QQ 开放平台现有回调配置是否包含该事件。
4. 由 AstrBot 管理员在目标群发送 `/设置菜单`，为当前群安装原生指令面板；群管理员可用 `/菜单状态` 查询。重复设置会识别并更新本插件的当前群面板，不会不断新建。每群占用 1 份面板，机器人总额度为 20 份，也包含机器人已有的其他面板。
5. 点击 QQ 指令菜单中的命令，补齐参数后发送；也可以发送 `/菜单` 打开消息快捷按钮，或直接使用 `/禁言 @成员 10m`。机器人只能接收 @它的消息时，请同时 **@机器人**。如果消息按钮尚未开放，发送 `/帮助` 使用文本命令，或关闭 `use_markdown`。

项目仓库：[diaomin66/astrbot_plugin_qqofficial_admin](https://github.com/diaomin66/astrbot_plugin_qqofficial_admin)。可在 AstrBot 插件管理中使用该仓库地址安装，也可以克隆仓库或下载安装包，再按上述目录结构安装。

`qq_official_webhook` 用户继续使用 AstrBot 已配置的回调地址。本插件不新增 HTTP 监听服务、不另开 webhook、不修改 AstrBot 源码，也不替换框架的 QQ 事件分发。

当前没有可用于部署的真实机器人账号，仓库提交不会自动给你的机器人安装菜单。更新或安装插件后，请由 AstrBot 管理员在每个需要菜单的群发送一次 `/设置菜单`。该操作只管理本插件为当前群建立的专属面板；`/移除菜单` 也仅移除这份面板，不改动其他用途或其他群的菜单。

## 首次配置

在目标群发送：

```text
/身份
```

回复包含实际的平台 ID、群 OpenID、成员 OpenID，以及可直接复制的受信任管理员配置项，例如：

```text
qq-bot-prod|GROUP_OPENID|MEMBER_OPENID
```

将这一完整字符串作为 `trusted_admins` 列表的一项填入 WebUI。平台 ID 是 AstrBot 中该连接的实际 ID，**不是固定填写 `qq_official`**；群 OpenID 不是 QQ 群号，成员 OpenID 不是 QQ 号或昵称。同一人跨机器人/群的身份应按实际值分别配置。

权限按以下顺序判断：

1. 当前群必须通过 `allowed_groups` 限制；此限制也适用于 AstrBot 管理员。
2. AstrBot `event.is_admin()` 为真的管理员可以操作本群及机器人级策略。
3. `trusted_admins` 精确匹配「平台 ID + 群 OpenID + 成员 OpenID」时，可以操作该群，但不能管理全局策略。
4. 开启 `allow_group_admins` 时，插件实时请求官方成员信息，允许 `member_role=owner/admin` 的真实用户操作该群；接口失败不会默认放行。

如果成员信息接口尚无白名单，自动识别群管理员会失败。此时由 AstrBot 管理员配置 `trusted_admins`，仍需目标操作本身的腾讯接口权限。普通群成员可以打开帮助、身份和基础菜单，查询管理数据和执行操作仍会校验权限。

原生指令面板的管理项设置 `only_admin=true`，QQ 客户端仅允许群主或群管理员点击；菜单和帮助项对所有成员开放。拥有 AstrBot 管理权限但不是该 QQ 群管理员的用户，可以手动发送命令。菜单的客户端权限不替代上述服务端鉴权。`/设置菜单` 和 `/移除菜单` 使用机器人级资源，仅允许 AstrBot 管理员操作；`/菜单状态` 按普通群管理查询权限处理。

**管理回复是群消息，群内所有成员都可能看到正文。** 面板按钮仅限制谁能点击，不会让成员信息、入群验证回答、OpenID 或操作结果变成私密消息。管理员应在适合公开这些信息的群中使用相关命令。

## 配置项

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 启用插件 |
| `allowed_groups` | `[]` | 允许的群 OpenID；空列表允许机器人所在的所有群 |
| `allow_group_admins` | `true` | 通过官方成员信息实时验证群主/管理员；成员接口需白名单 |
| `trusted_admins` | `[]` | 精确格式 `平台ID\|群OpenID\|成员OpenID`，只授权对应群 |
| `use_markdown` | `true` | 使用原生 Markdown 和按钮；明确被平台拒绝时降级为文本 |
| `request_timeout` | `15` | 官方接口超时，5–60 秒；写操作超时不自动重试 |
| `audit_retention_days` | `30` | 审计保留期，1–365 天 |
| `remember_messages` | `true` | 在内存中记录最近两分钟可见消息的 ID、作者 OpenID 和时间，便于撤回 |

不需要在插件中再次填写 AppID、AppSecret 或 access_token。插件复用当前 AstrBot QQ 适配器的令牌刷新机制，并向官方 `https://api.bot.qq.com` 发起请求。

## 命令一览

所有命令直接在 QQ 群内使用，例如 `/禁言 @成员 10m`，无需先写群管前缀。旧版 `/群管 ...` 和 `/qqadmin ...` 保留兼容。下面的 `@成员` 表示在 QQ 中插入的真实成员提及，也可以替换成 **member_openid**；`成员ID` 表示 **member_openid**，`消息ID` 表示官方消息 ID，`申请ID` 来自入群申请列表，`游标` 使用上一页返回的 `next_cursor`。有「下一页」按钮时可直接点击。

### 查询和导航

| 命令 | 说明 |
|---|---|
| `/菜单` | 打开消息内的管理快捷按钮；旧别名 `/面板` |
| `/设置菜单` | 安装或更新本插件为当前群建立的官方指令面板；仅 AstrBot 管理员 |
| `/菜单状态` | 查询本插件当前群官方指令面板；群管理员可用 |
| `/移除菜单` | 删除本插件为当前群建立的官方指令面板；仅 AstrBot 管理员 |
| `/帮助` | 查看本插件命令帮助 |
| `/身份` | 查看平台、群、操作者 OpenID；别名 `我的ID` |
| `/信息` | 群基本信息 |
| `/状态` | 机器人群内状态 |
| `/成员 [游标]` | 成员列表，每页最多 30 人 |
| `/成员详情 @成员` | 指定成员详情及常用管理按钮，也可填写成员 OpenID |
| `/禁言状态` | 当前成员禁言及全员/定时/周期禁言配置 |
| `/黑名单 [游标]` | 群黑名单，默认每页 20 条 |
| `/入群 [游标]` | 按需拉取入群申请，每页 4 条，逐条提供通过/拒绝按钮 |
| `/最近消息` | 插件最近两分钟实际看到的消息 ID；不是群聊天记录搜索 |
| `/日志` | 本群最近 10 条操作记录 |
| `/策略列表 [游标]` | 当前机器人自动审批策略，默认每页 20 条；仅 AstrBot 管理员 |
| `/结果 令牌 段号` | 翻阅同一次查询的完整结果；段号从 0 开始，优先使用「上一段/下一段」按钮 |

长结果会完整分段，不会截掉成员或申请记录。「上一段/下一段」翻阅当前接口页的内容，「下一页」请求官方接口的下一页；两者各自保留上下文。结果快照只在内存保存，绑定平台、群和操作者，5 分钟后过期，重启后需重新查询。策略结果翻段时也会重新检查 AstrBot 管理员权限。

### 成员、禁言与审批

| 命令 | 说明 |
|---|---|
| `/禁言 @成员 [时长]` | 增加成员禁言，不填时长默认 10 分钟 |
| `/禁言 @成员A @成员B [时长]` | 同时禁言多个成员 |
| `/更新禁言 @成员 [时长]` | 更新禁言到期时间，不填时长默认 10 分钟 |
| `/解禁 @成员` | 解除禁言，可同时 @多个成员 |
| `/移出 @成员` | 移出成员，可同时 @多个成员 |
| `/移出 @成员 拉黑` | 移出并同时加入群黑名单 |
| `/拉黑 成员ID[,成员ID]` | 将已经不在群中的成员加入群黑名单 |
| `/取消拉黑 成员ID[,成员ID]` | 移出群黑名单 |
| `/同意 成员ID 申请ID` | 同意指定入群申请 |
| `/拒绝 成员ID 申请ID [理由]` | 拒绝指定申请 |
| `/拒绝 成员ID 申请ID --拉黑 [理由]` | 拒绝并拉黑 |

成员操作单次最多 20 个，可以连续 @多名成员，也可以填写英文逗号分隔的 OpenID。`/禁言` 和 `/更新禁言` 不填时长默认 10 分钟；指定时长支持 `600`（秒）、`10m`、`1h`、`7d`，也支持 `10分钟`、`1小时` 等，最长 30 天，从实际执行时开始计算。平台只允许禁言普通成员，不能禁言群主、管理员或机器人。独立黑名单操作通常用于已经离群、无法再直接 @的成员，请填写其成员 OpenID。

```text
/成员
/禁言 @成员
/禁言 @成员A @成员B 10m
/禁言 MEMBER_A,MEMBER_B 10m
/更新禁言 @成员A 1h
/解禁 @成员A
/移出 @成员B 拉黑
/入群
/同意 MEMBER_C ORIGINAL_REQUEST_ID
/拒绝 MEMBER_D ORIGINAL_REQUEST_ID --拉黑 验证信息不符合入群要求
```

示例 ID 均需替换成接口返回的真实值。审批必须使用对应申请的原始 `join_request_id`，不能只根据成员 ID 猜测当前申请；申请面板上的按钮会自动携带真实申请 ID。

### 自动审批策略

这些操作影响整个机器人可能关联的多个群，**包括策略列表在内均仅允许 AstrBot 管理员**。创建关联群使用 OpenID 或 QQ 群号二选一。JSON 的字段名和字符串需使用双引号。

| 命令 | 说明 |
|---|---|
| `/策略创建 JSON` | 创建策略；可用 `group_openids` 或 `group_ids`，以及 `is_enable`、`expire_at`、`remark` |
| `/策略修改 策略ID JSON` | 修改 `is_enable`、`expire_at`、`remark` 或 `group_action` |
| `/策略删除 策略ID` | 删除策略 |
| `/策略执行 策略ID` | 对全部关联群扫描申请，自动通过白名单命中项；异步约 10 分钟 |
| `/策略白名单 策略ID add QQ号[,QQ号]` | 增加 QQ 号码白名单 |
| `/策略白名单 策略ID del QQ号[,QQ号]` | 删除 QQ 号码白名单 |

```text
/策略创建 {"group_openids":["GROUP_OPENID"],"is_enable":"off","remark":"社群成员入群"}
/策略列表
/策略白名单 st_EXAMPLE add 12345678,23456789
/策略修改 st_EXAMPLE {"is_enable":"on"}
/策略修改 st_EXAMPLE {"group_action":{"op":"add","group_openids":["OTHER_GROUP_OPENID"]}}
/策略执行 st_EXAMPLE
/策略修改 st_EXAMPLE {"is_enable":"off"}
/策略删除 st_EXAMPLE
```

也可用 `{"group_ids":[123456789]}` 创建按 QQ 群号关联的策略；`group_ids` 是整数数组，不能同时传 `group_openids`。后续关联群增删须沿用创建时的标识形式。`is_enable` 是字符串 `on/off`，默认 `on`；不传 `expire_at` 默认一年，指定时使用带时区 RFC3339，例如 `2027-11-11T18:00:00+08:00`。

官方上限为每机器人 20 个策略、每策略关联最多 100 个群、白名单 10 万号码、每次增删最多 10000 号码。**策略白名单填写 QQ 号，不是成员 OpenID。** 聊天命令还受 16000 字符上限约束，较长批量操作需要分次提交；参数完整且鉴权通过后立即执行。

### 消息

| 命令 | 说明 |
|---|---|
| `/撤回 消息ID` | 撤回两分钟内的指定消息；权限最终由 QQ 判断 |
| `/通知 内容` | 向当前群发送普通文本通知 |
| `/全体通知 内容` | 使用官方标签 @全体成员并发送通知；机器人须为管理员，每群每天 1 次 |

```text
/通知 今天的讨论从晚上八点开始。
/全体通知 今晚八点进行例行维护，请提前保存进度。
/最近消息
/撤回 OFFICIAL_MESSAGE_ID
```

通知内容限 1–1500 字符。这里的「通知」是群消息，**不是 QQ 群公告 API**。@全体标签由专门命令生成，普通通知不会接受手工插入的 QQ 交互标签。被动回复有效期为 5 分钟，每条消息最多回复 5 次，平台还会检查消息频率和权限。

## 直接执行、按钮与审计

发送参数完整的写命令后，插件校验平台、群、操作者、当前管理权限和参数，登记执行回执后立即调用官方接口。成员详情中的「禁言10分钟」「移出成员」和入群申请中的「通过」「拒绝」等按钮已经包含目标参数，点击即可执行；危险操作仅用红色标识，不弹出 `action.modal`，也没有第二次确认步骤。

QQ 原生指令菜单和消息输入按钮会先将命令填入输入框，用户选择真实 @成员、补齐参数并发送。这是 QQ 的输入行为；插件收到完整命令后直接执行。消息回调按钮使用 `permission.type=0` 限定原操作者，回调仍经服务端重新鉴权，不能只靠客户端按钮权限授权。

SQLite 将执行回执和初始审计记录在同一事务中写入，绑定平台、群、操作者与请求标识。消息以原消息 ID 防重，按钮以每次生成的独立操作 ID 防重；同一消息重复投递、同一按钮连续点击或并发点击，在 **24 小时**内不会重复发起写请求，重启后仍有效。重新发送一条命令或打开新菜单会生成新的请求，属于新的操作。

若平台明确拒绝 Markdown/按钮消息，插件尝试提供文本入口；网络超时不会因降级而盲目重复发送。写接口超时或结果无法确定时显示「操作结果尚未确认」，保留已登记回执且不自动重试。请先查询真实状态，再决定是否发送新指令。执行中进程中断的记录在重启后标记为结果未知。批量拉黑的部分失败会单独提示。策略执行返回成功只表示平台已受理异步任务。

`INVALID_RESPONSE` 是插件发现响应无法解析或关键字段不符合预期时生成的诊断代码，并非 QQ 平台的权限错误码。v1.2.1 会区分修改请求发出前后的失败：前置查询失败记为 `failed`，已尝试修改且无法核实结果时记为 `unknown`。菜单创建/更新遇到异常响应时可进行一次只读核实，但不会重复发送写请求。详情见 [菜单异常排查](docs/COMMAND_MENU.md#异常响应与排查)。

SQLite 文件 `admin.sqlite3` 位于 AstrBot `StarTools.get_data_dir("astrbot_plugin_qqofficial_admin")` 分配的插件数据目录。执行回执保留 24 小时，审计按 `audit_retention_days` 保留；过期数据在启动及每分钟清理。审计记录操作者、范围、操作类型、参数和结果，通知正文替换为字符数，不写入执行回执或审计。插件不保存应用凭据，也不长期保存群聊天正文。「最近消息」仅在内存保留 ID、作者和时间，重启后清空，可通过 `remember_messages=false` 关闭。

从旧版升级时，插件会删除旧 `pending` 待确认表，旧记录立即失效；`/确认`、`/取消` 已停用，只会提示重新发送管理指令。旧写操作按钮缺少新的操作 ID 时会被拒绝，请重新发送 `/菜单` 并打开所需操作。升级不会将旧待执行任务自动执行。

## 兼容性与已知边界

- QQ 官方群消息和 AstrBot 原生按钮回调是当前事件入口；频道、私聊、其他协议适配器不在支持范围。
- 上游 `qq-botpy==1.2.1` / AstrBot 当前分发链没有完整转发新增群成员和入群申请事件。本插件不通过修改核心或全局替换 SDK 来伪造接入，**不提供自动入群欢迎、成员退群通知或新申请实时推送**；使用 `/入群` 主动拉取申请。具体说明见 [事件说明](docs/EVENTS.md)。
- 官方查询接口能读全员、定时和周期禁言状态，但公开写接口只允许成员禁言。因此没有设置全员禁言/定时禁言的命令。
- QQ 群目录未公开设置管理员、修改群名/群名片、精华消息、群公告等对应 API，插件不会混用频道接口。
- 机器人可能只能看到 @ 它的消息。「最近消息」和撤回入口只反映实际可见内容，不承诺能读取全部群消息或历史记录。
- QQ 原生指令面板与消息输入按钮在群里填入输入框；用户补齐参数后发送。成员详情、入群审批等已带完整参数的消息回调按钮直接执行。`enter=true` 自动发送仅适用于单聊。
- 未来 AstrBot 或 botpy 的原生按钮/令牌对象变更可能需要适配更新。插件要求的最低版本用于支持目前采用的原生按钮接口。
- **尚未使用真实机器人账号做在线联调，也未为真实账号自动安装菜单**。本地测试覆盖协议构造、权限、直接执行、防重、审计、消息路由和错误处理；接口白名单、客户端显示及实际事件投递仍需在你的机器人账号上验证。部署后在目标群发送 `/设置菜单` 安装。

## 本地验证

在项目根目录使用 Python 3.12 或更高版本：

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m compileall -q main.py qq_admin tests
```

测试使用标准库 `unittest` 和模拟传输，不会调用真实 QQ 管理接口。测试内容包括群管理与原生菜单接口契约、短命令与原生 @成员解析、默认禁言时长、分页和输入边界、跨群/跨用户按钮校验、直接执行与并发防重、策略权限、凭证复用和网络错误处理。实际部署后先通过 `/身份`、`/状态` 和 `/信息` 检查连接及授权，再由 AstrBot 管理员执行 `/设置菜单`，在可管理的测试群验证所需功能。
